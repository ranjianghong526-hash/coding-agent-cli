# 代码审查

先阅读真实 diff 和附近的调用链，再给出结论。

1. 找出行为变化，以及能触发这些变化的输入。先明确需要审查的改动范围。
2. 检查错误路径、边界条件，以及现有调用方的兼容性。
3. 确认测试既覆盖预期行为，也覆盖最可能发生的回归。
4. 只报告可执行的问题：受影响的文件、具体失败方式和最小安全修复建议。
5. 总结没有发现问题的范围、已经执行的验证与尚未验证的部分。

只有改动涉及数据库 schema 或数据迁移时，才读取本 Skill 根目录下的
`references/database.md`；普通代码审查不需要加载它。

用户只要求总结审查步骤时，解释流程即可，不执行命令或修改代码。
